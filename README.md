# ⚖️ Thai Tax RAG: ระบบถาม-ตอบภาษีเงินได้บุคคลธรรมดา

แชตบอตตอบคำถามภาษีเงินได้บุคคลธรรมดา โดยค้นหาจากเอกสารกฎหมายและคู่มือของกรมสรรพากร แล้วให้ AI สรุปคำตอบพร้อมอ้างอิงชื่อไฟล์และเลขหน้า

```
คำถาม ──► AI เขียนคำค้นใหม่จากบริบทแชต (เฉพาะเมื่อมีคำถามก่อนหน้า)
              │
              ▼
          bge-m3 ค้นเอกสารใน ChromaDB (Top-K ท่อน)
              │
              ▼
คำตอบพร้อมอ้างอิง ◄── AI (Ollama Cloud · gemma4:31b)
```

**พฤติกรรมการตอบ** (กำหนดใน system prompt ของ `app_chat_streamlit.py`):
- ตอบจาก**เอกสารอ้างอิงที่ค้นได้เท่านั้น** ถ้าเอกสารไม่มีข้อมูลที่เกี่ยวข้อง จะแจ้งว่าไม่พบข้อมูลแทนการเดา
- ไม่คำนวณยอดภาษีเป็นตัวเลขอย่างละเอียด อธิบายเฉพาะหลักเกณฑ์ เงื่อนไข และโครงสร้างอัตราภาษีตามเอกสาร
- อ้างอิง `[ชื่อไฟล์ หน้า N]` ท้ายข้อความ และปิดท้ายด้วยหัวข้อ **📚 สรุปแหล่งอ้างอิง**
- ใต้คำตอบมีส่วน **📄 ดูเอกสารอ้างอิง** แสดงท่อนเอกสารที่ค้นได้ พร้อมเลขหน้าและ % ความเกี่ยวข้อง

## 2. ติดตั้งครั้งแรก

ต้องมี **Python 3.12 ขึ้นไป** (เครื่องนี้ใช้ Python 3.14 จาก Miniconda)

```bash
python -m venv .venv
```
```bash
.venv\Scripts\python -m pip install -r requirements.txt
```

- ครั้งแรกที่รันแอป ระบบจะดาวน์โหลดโมเดล **bge-m3** (~2.3 GB) ไว้ในเครื่อง ครั้งต่อไปไม่ต้องโหลดใหม่
- ⚠️ ถ้าเจอ `DLL load failed ... An Application Control policy has blocked this file` แปลว่า Windows **Smart App Control** บล็อกไลบรารี Python อยู่ ต้องปิดที่ Windows Security → App & browser control → Smart App Control

## 3. ตั้งค่า `.env`

คัดลอก `.env.example` เป็น `.env` แล้วใส่ค่า:

| ตัวแปร | จำเป็น | ค่าที่ใช้อยู่ / คำอธิบาย |
|---|---|---|
| `OLLAMA_API_KEY` | ✅ | สร้างได้ที่ https://ollama.com/settings/keys |
| `LLM_PROVIDER` | | `ollama` (ค่าเริ่มต้น) หรือ `openrouter` (ต้องใส่ `OPENROUTER_API_KEY` แทน) |
| `AI_MODEL` | | `gemma4:31b` (ค่าเริ่มต้นของ Ollama) เปลี่ยนโมเดลได้ที่บรรทัดนี้ ไม่ต้องแก้โค้ด |
| `EMBEDDING_MODEL` | | `BAAI/bge-m3` ห้ามเปลี่ยน ถ้าไม่ได้สร้างดัชนีใหม่ด้วยโมเดลเดียวกัน |
| `EMBEDDING_DTYPE` | | `float16` (ค่าเริ่มต้น ใช้หน่วยความจำ ~2 GB และให้ผลค้นหาเหมือน `float32`) |
| `PERSIST_CHAT_HISTORY` | | ค่าเริ่มต้น `true` = บันทึกแชตลง `chat_history.json` (ใช้บนเครื่องตัวเอง) / `false` = เก็บแค่ใน session ผู้ใช้แต่ละคนเห็นเฉพาะแชตตัวเอง (ใช้ตอน deploy) |
| `APP_PASSWORD` | | ถ้าตั้งค่า ต้องใส่รหัสผ่านก่อนใช้งาน (ใช้ตอน deploy) |

แก้ API Key หรือ `AI_MODEL` ใน `.env` แล้วกดรีเฟรชหน้าเว็บได้เลย ไม่ต้องรีสตาร์ทแอป ส่วน `EMBEDDING_MODEL` / `EMBEDDING_DTYPE` **ต้องรีสตาร์ทแอป** เพราะโมเดลถูกโหลดค้างไว้ (cache)

## 4. รันแอปแชต

รันจากโฟลเดอร์โปรเจกต์:

```bash
.venv\Scripts\python -m streamlit run app_chat_streamlit.py
```

เปิด http://localhost:8501 แล้วหยุดแอปด้วย `Ctrl+C`

> ❗ ห้ามใช้ `python app_chat_streamlit.py` (ไม่เปิดเว็บ) และระวัง `python` ของ conda `(base)` ที่ไม่มีแพ็กเกจของโปรเจกต์ ให้ใช้ `.venv\Scripts\python` เสมอ

**ตัวเลือกในแถบด้านข้าง:**
- **Top-K** (ค่าเริ่มต้น 4): จำนวนท่อนเอกสารที่ค้นมาให้ AI อ่าน ถ้าคำถามมีหลายประเด็นให้เพิ่มเป็น 6–8
- **Temperature** (ค่าเริ่มต้น 0.5): ค่าต่ำ (เช่น 0.0) ได้คำตอบตรงและคงที่ ค่าสูงขึ้นจะอธิบายเป็นธรรมชาติขึ้นแต่แต่ละครั้งต่างกันมากขึ้น
- **🗑️ ล้างประวัติการสนทนา:** ควรกดเมื่อเปลี่ยนเรื่องคุย

## 5. เพิ่มหรือเปลี่ยนเอกสาร

1. วางไฟล์ `.pdf` หรือ `.md` ใน `pdf_docs/`
2. **หยุดแอปแชตก่อน** (`Ctrl+C`)
3. สร้างดัชนีใหม่ (ใช้เวลาประมาณ 10 นาทีบนเครื่องนี้):
   ```bash
   .venv\Scripts\python app_rag_openrouter.py
   ```
4. ตรวจสรุปจำนวนท่อนต่อไฟล์ตอนจบ ไฟล์ที่ได้ **0 ท่อน** คือไฟล์สแกน (เป็นรูปภาพ) ซึ่งต้องแปลงเป็นข้อความก่อน เช่น ทำเป็น `.md`
5. เปิดแอปใหม่
6. ถ้า deploy ไว้ ให้อัปโหลดดัชนีใหม่ขึ้น GitHub แล้ว Streamlit Cloud จะอัปเดตเอง:
   ```bash
   git add chroma_tax_db
   ```
   ```bash
   git commit -m "Update document index"
   ```
   ```bash
   git push
   ```

**สิ่งที่สคริปต์ทำกับเอกสาร:**
1. **แปลงเป็นข้อความ:** PDF แปลงเป็น Markdown ทีละหน้าด้วย pymupdf4llm (จำเลขหน้าไว้) ส่วนไฟล์ `.md` อ่านตามที่เขียนไว้
2. **ทำความสะอาดข้อความ PDF:** แก้สระอำแตก (`ำา` → `ำ`), ต่อสระและวรรณยุกต์ที่ถูกแยกด้วยช่องว่าง (`ค ่ า` → `ค่า`), ลบแท็ก `<br>` `<mark>` `<sup>` `<u>` และเครื่องหมายข้อความจากรูปภาพ (เก็บข้อความด้านในไว้)
3. **ตัดเป็นท่อน:** ตามหัวข้อ `#`/`##`/`###` ก่อน แล้วตัดย่อยไม่เกิน 700 ตัวอักษร (ซ้อนทับ 80)
4. **แปลงเป็นเวกเตอร์และบันทึก:** ใช้ bge-m3 (1,024 มิติ) บันทึกลง ChromaDB พร้อมชื่อไฟล์และเลขหน้า แล้วลบโฟลเดอร์ดัชนีเก่าให้อัตโนมัติ

**ข้อควรรู้:**
- สคริปต์จะ **ลบดัชนีเดิมทั้งหมด** แล้วสร้างใหม่จากทุกไฟล์ใน `pdf_docs/` ถ้าหยุดกลางคัน ฐานข้อมูลจะว่างจนกว่าจะรันจบ
- PDF อ้างอิงเป็น `[ไฟล์ หน้า N]` ส่วน `.md` อ้างอิงเป็นชื่อไฟล์อย่างเดียว (ไม่มีเลขหน้า)
- ใน `.md` ให้ใช้หัวข้อ `#`, `##`, `###` แบ่งเนื้อหา ระบบจะตัดท่อนตามหัวข้อและเก็บชื่อหัวข้อไว้ในแต่ละท่อน

## 6. Deploy บน Streamlit Community Cloud (ฟรี)

1. อัปโหลดโปรเจกต์ขึ้น GitHub (ตั้งเป็น Private) ด้วย `git add .` → `git commit` → `git push` ตรวจว่า **ไม่มี** `.env` แต่ **มี** `chroma_tax_db/`
2. ที่ https://share.streamlit.io → Create app → เลือก repo และไฟล์ `app_chat_streamlit.py`
3. Advanced settings: เลือก Python 3.12 และใส่ Secrets:
   ```toml
   OLLAMA_API_KEY = "your-ollama-key"
   LLM_PROVIDER = "ollama"
   AI_MODEL = "gemma4:31b"
   PERSIST_CHAT_HISTORY = "false"
   APP_PASSWORD = "choose-a-password"   # ไม่บังคับ ถ้าไม่ใส่ แอปจะเปิดได้เลยโดยไม่มีหน้ารหัสผ่าน
   ```
4. Deploy (ครั้งแรกใช้เวลาหลายนาที เพราะต้องติดตั้ง torch และโหลด bge-m3)

แอปโหลด bge-m3 แบบ fp16 จึงใช้หน่วยความจำประมาณ 2.0 GB (สูงสุดตอนเริ่ม ~2.6 GB) ซึ่งอยู่ในขีดจำกัด ~2.7 GB ของ Streamlit Cloud ถ้าจะใช้ VPS แทน ควรมี RAM อย่างน้อย 4 GB

**ประวัติแชตบนเว็บที่ deploy:** เมื่อตั้ง `PERSIST_CHAT_HISTORY = "false"` แชตจะเก็บอยู่แค่ใน session ของแท็บนั้น (`st.session_state` บนเซิร์ฟเวอร์) ผู้ใช้แต่ละคนเห็นเฉพาะแชตของตัวเอง แต่**แชตจะหายเมื่อรีเฟรชหน้า เปิดแท็บใหม่ หรือแอปรีสตาร์ท** ซึ่งเป็นพฤติกรรมปกติ การเก็บแชตถาวรต้องใช้ที่เก็บแยกต่อผู้ใช้ เช่น localStorage ของเบราว์เซอร์ หรือฐานข้อมูลภายนอกพร้อมระบบล็อกอิน

## 7. แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| `ModuleNotFoundError: No module named 'streamlit'` | ใช้ Python ผิดตัว ให้ใช้ `.venv\Scripts\python -m streamlit run ...` |
| `DLL load failed ... Application Control policy` | Smart App Control บล็อกอยู่ (ดูข้อ 2) |
| `⚠️ ... ปฏิเสธ API Key (401)` | Key ใน `.env` ผิดหรือหมดอายุ แก้แล้วรีเฟรชหน้า |
| `⚠️ ... เกินโควตา (429)` | ใช้งานเกินโควตาของผู้ให้บริการ รอสักครู่ หรือเปลี่ยน `AI_MODEL` |
| `Port 8501 is not available` | มีแอปเปิดอยู่แล้ว ปิดหน้าต่างเดิม หรือใช้ `--server.port 8502` |
| `ค้นหาเอกสารไม่สำเร็จ ... Embedding Model ไม่ตรงกับฐานข้อมูล` | `EMBEDDING_MODEL` ไม่ตรงกับตอนสร้างดัชนี ให้ใช้ `BAAI/bge-m3` หรือสร้างดัชนีใหม่ |
| ตอบว่าไม่พบข้อมูล ทั้งที่เอกสารน่าจะมี | เพิ่ม Top-K แล้วเปิด "📄 ดูเอกสารอ้างอิง" ดูคะแนนความเกี่ยวข้อง ถ้าต่ำกว่า ~60% เอกสารอาจไม่มีเรื่องนั้นจริง |
| แชตหายหลังรีเฟรชหน้า (บนเว็บที่ deploy) | เป็นพฤติกรรมปกติ แชตเก็บอยู่แค่ใน session ของแท็บนั้น (ดูข้อ 6) |
| Push แล้วแต่ GitHub ไม่มี commit ใหม่ / `rejected … fetch first` | ตรวจว่าคำสั่ง push จบด้วยบรรทัด `xxxxxxx..yyyyyyy  main -> main` ถ้าถูกปฏิเสธเพราะ GitHub มี commit ที่เครื่องไม่มี (เช่น `.devcontainer` ที่ Streamlit เพิ่ม) ให้รัน `git pull --rebase` แล้ว `git push` |
